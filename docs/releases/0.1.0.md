# Contextopus 0.1.0

**Initial standalone release of Contextopus** in [`https://github.com/pikiby/contextopus`](https://github.com/pikiby/contextopus): one ready-to-use local **Core** packaged cleanly alongside **downloadable optional add-on modules**, unified document collections, interactive web management and seven coding assistant integrations.

---

## Highlights

- **Standalone Ready Core:** Project contexts, shared instructions, notes, agent profiles, teams, skill catalogs, session summaries and image metadata live in one unified Core runtime (`core/instructions/` and `core/documents/<collection>/`), backed by LanceDB semantic search and configurable selection algorithms.
- **Separate Downloadable Add-on Modules:** Optional capabilities stay outside the base Core installer and ship as independent `.zip` module archives in this release — starting with **`Session Search`** (`contextopus-module-session-search-0.1.0.zip`).
- **Three-Tool MCP Surface + Unified `/w` Skill:** Connected coding assistants use `guide()`, `read()` and `write()` over HTTP MCP (`http://127.0.0.1:8765/mcp`) routed through a single `/w` skill. `guide(procedure=...)` delivers base rules, module routes and live operation schemas.
- **Path-Aware Contexts & Conditional Rules:** `core.context_read` matches `workdirs` automatically (longest prefix match) or resolves explicit context IDs/slugs, returning resolved `instructions`, topic-based `route_map` entries, `requires_read` payloads and per-context settings.
- **Preview-Guarded Mutations & Git History:** `core.documents_preview` validates changes, checks potential duplicates within the target collection, computes unified diffs and returns exact revision/approval contracts before `core.documents_save` / `core.documents_delete` commit and snapshot in Git.
- **Interactive Local Web UI:** `contextopus web` (`http://127.0.0.1:41860/`) adds **Contexts and rules** toggles (`documents_approval_required`, `instructions_approval_required`, `git_history_enabled`), **Edit history** Git commits with line diffs and targeted path rollback, plus **Session sources** provider toggles alongside the searchable **Library**.

| `contextopus_core-0.1.0.tar.gz` | Source distribution |

### 2. Optional add-on modules *(install on top of Core as needed)*

| Asset | Purpose |
|---|---|
| `contextopus-module-session-search-0.1.0.zip` | **Session Search** (`session_search` 0.1.0): SQLite FTS5 lexical transcript indexing & reading for Codex (including `.jsonl.zst`), Claude Code, Antigravity, OpenCode and Crush |

Install after Core is set up:

```console
contextopus --root /path/to/contextopus-data modules install session_search --source contextopus-module-session-search-0.1.0.zip --plan
contextopus --root /path/to/contextopus-data modules install session_search --source contextopus-module-session-search-0.1.0.zip
```

## Verification and known limits

- **Automated CI matrix:** GitHub Actions runs on `ubuntu-latest`, `macos-latest` and `windows-latest` with Python **3.12** and **3.13**, executing `pytest`, `tests/web_frontend_smoke.cjs`, `uv build --no-sources`, `scripts/build_release.py` and `scripts/verify_release.py`.
- **What automated checks cover:** Core document/search/settings/relocation/module/integration suites (`pytest`), DOM/API interaction smoke checks (`web_frontend_smoke.cjs`), archive structure & checksums (`SHA256SUMS` validated locally and in CI), license files and `session_search` add-on packaging (`zstandard>=0.22` included in Core runtime dependencies).
- **Boundaries not covered by package tests:** Package verification does not test every host client version live on Windows/macOS, nor does it download or run real HuggingFace embedding weights offline (semantic tests use deterministic test embeddings). After installing or connecting a client, reload MCP and run `guide()` + `read(operation="core.status")` inside your target assistant.
